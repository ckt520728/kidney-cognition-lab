A Benchmark-Aware Agentic Literature-Review Pipeline: Recall–Precision Trade-offs and a Demonstration on Wearables in Aging Neuroscience

Kuo-Ta Chu, MD
Kidney–Cognition Lab · Nephrology & Cognitive Neuroscience
PREPRINT / LAB TECHNICAL REPORT · v1 · 2026-07-21

Abstract

Background. Keeping up with the literature is a Level-3 knowledge task — it only creates value when it ends in a shipped, decision-changing output — yet most tooling stops at retrieval. We describe an agentic literature-review pipeline that couples a deterministic search-and-organize engine with a benchmark-aware judgment layer, and we quantify a recall–precision trade-off that any multi-source search must confront.

Methods. The engine searches PubMed, arXiv, and a local knowledge vault; de-duplicates by DOI then normalized title; screens against explicit inclusion criteria; and exports a digest, a colour-coded workbook, a benchmark chart, and a citation bundle. Two methodological features are evaluated: (i) per-source query overrides, allowing a precise MeSH-tagged PubMed query alongside plain-text queries for preprint servers; and (ii) a broad+precise merge that unions a wide keyword run with a precise MeSH run under the same de-duplication.

Results. On the topic "wearable devices in aging neuroscience," a keyword-only run returned 94 unique records but with ~15/60 off-topic PubMed hits; a MeSH run returned 119 records with 0/70 off-topic hits, and surfaced stronger, externally-validated studies the keyword run missed — but dropped a top prodromal-Parkinson's marker because its cohort framing failed the age clause. Merging the two runs (213→179 unique) recovered that marker while retaining the precise additions, at the cost of re-admitting 11 off-topic records that the judgment layer then excluded.

Conclusion. Precision and recall are separately controllable in agentic review, and neither query alone is sufficient; a broad+precise merge with an explicit judgment layer is a practical operating point. We release the design and the worked example as a reproducible template.

Keywords: literature review · agentic AI · MeSH · information retrieval · digital biomarkers · aging · personal knowledge management

1. Introduction

Personal knowledge management (PKM) has three maturity levels [1]. Level 1 is storage: notes exist to be found again. Level 2 is a thinking partner: notes link and generate internal feedback. Level 3 is model revision: an output is shipped into the world, and reality answers back. Most literature-review workflows — and most tools that automate them — never leave Level 1. They retrieve; they do not force a decision, and so they do not change one.

A literature review reaches Level 3 only when it terminates in an artefact a busy investigator can act on: a ranked, interpreted, benchmark-anchored digest, not a wall of abstracts. This paper describes a pipeline built around that requirement, separating the mechanical problem (find, de-duplicate, organize) from the judgment problem (score relevance, compare to the field standard, decide what matters). We then use a concrete topic to measure a trade-off that governs any such system: the tension between recall (missing nothing) and precision (surfacing only what is relevant).

2. System design

The pipeline is a small command-line engine (the mechanical layer) driven by an agent that supplies the judgment layer. The stages are:

search  →  dedup  →  screen  →  synthesize  →  export
(PubMed/arXiv/vault)  (DOI→title)  (criteria)  (digest)   (workbook, chart, citations)
Figure 1. The engine is deterministic and reproducible; the agent supplies judgment. Separating the two lets the same corpus be re-scored under different criteria without re-querying.

2.1 The mechanical engine

Each source implements a common interface returning a list of records; adding a source is a drop-in. De-duplication keys on DOI when present, else a normalized title hash, and prefers the richer record on collision. Screening marks each record include, exclude, or needs-review. Every network call has an explicit timeout, and a single source failing (a timeout, a parse error) never aborts the others — it is reported and its results are empty. This graceful-degradation rule is a hard design constraint: a missing API key or vault path silently disables that capability rather than crashing the run.

2.2 The judgment layer

On top of the screened corpus, the agent assigns a 0–100 relevance score (High ≥85 / Medium 60–84 / Low <60), extracts the headline quantitative result, and — critically — places every number next to a field-standard benchmark, stating whether it is above, at, or below and by how much. Benchmarks are approximate orientation values drawn from the wider literature and are always labelled as such; the layer never fabricates a statistic, marking absent values "not reported" and flagging them for follow-up.

3. Methodological contributions

3.1 Per-source query overrides

Bibliographic databases and preprint servers do not share a query language. A MeSH-tagged Boolean query — e.g. "Wearable Electronic Devices"[MeSH] AND "Aged"[MeSH] AND ("Cognition"[MeSH] OR "Gait"[MeSH]) — is high-precision on PubMed but returns essentially nothing on arXiv, which expects free text. The engine therefore accepts a default query plus per-source overrides, so a single de-duplicated run can pair a precise PubMed query with a plain-text arXiv query.

3.2 Broad + precise merge

Precision and recall pull in opposite directions, and — as Section 4 shows — a single query cannot maximize both. The engine can merge several prior runs into one de-duplicated corpus, enabling a deliberate strategy: run a wide keyword query for recall and a precise MeSH query for quality, then union them. Screening flags are preserved across the merge.

4. Demonstration: wearables in aging neuroscience

We ran the pipeline on "wearable devices in aging neuroscience," restricted to 2022 onward, across PubMed and arXiv, under three configurations: a broad keyword query; a precise MeSH query (with a plain arXiv override); and a merge of the two. Precision was audited by a title-level off-topic detector (pediatric, non-aging, or clearly unrelated records) and confirmed manually.

The MeSH query eliminated off-topic PubMed noise (from ~15/60 to 0/70) and, more importantly, surfaced stronger studies the keyword run missed — including externally-validated and pathology-confirmed designs. However, the precise query's "Aged"/older-adult clause dropped a top result from the keyword run: ActiTect, an actigraphy pipeline for prodromal-Parkinson's screening (REM-sleep behavior disorder) with AUROC 0.95 in development and 0.84–0.94 across three external cohorts. The merge recovered it — full recall — while retaining the MeSH additions, at the cost of re-admitting the 11 keyword-only off-topic records, which the judgment layer excluded explicitly (no silent dropping).

Key result. No single query was sufficient. The MeSH query was more precise and found better papers, yet lost a top marker to an over-strict clause; only the broad+precise merge achieved both precision (via the judgment layer) and full recall.

The fall-risk model's AUC of 0.967 is, in isolation, the most impressive number in the corpus; the benchmark read flags that with a positive predictive value of 6.25% and six fall events, the AUC is an artefact of class imbalance. Conversely, the highest-value studies (dementia prediction, ActiTect) win not on a single headline number but on external validation — precisely the property a benchmark-aware read is designed to reward.

5. Discussion

A Level-3 machine. The pipeline is, in PKM terms [1], an engine for reaching Level 3: it forces the review to terminate in shipped artefacts (this paper and its companion post among them) whose claims are exposed to scrutiny. The benchmark layer is the mechanism by which "reality answers back" inside the review itself — a claim that cannot beat its field reference, or that collapses under imbalance, is marked as such before it leaves the pipeline.

Recall–precision is an operating choice, not a fixed property. The demonstration shows both failure modes concretely: keyword search over-recalls (noise), a strict MeSH clause under-recalls (a lost top marker). The merge is not a universal answer but a defensible default when recall matters, provided an explicit judgment layer absorbs the re-admitted noise.

Limitations. (i) Benchmarks are approximate and hand-curated per topic; they orient interpretation but are not themselves systematically derived. (ii) Screening from titles and abstracts inherits their omissions — several headline statistics were "not reported" in the abstract and would require full-text retrieval. (iii) Results are a single-day snapshot of a moving literature; the pipeline is designed for scheduled re-runs, not one-shot completeness. (iv) The off-topic audit is heuristic and title-level. (v) This is a research-tooling report, not a systematic review conducted to PRISMA standards, and its findings about the wearables literature are illustrative rather than exhaustive.

6. Conclusion

Agentic literature review benefits from separating a deterministic mechanical engine from a benchmark-aware judgment layer, and from treating precision and recall as independently controllable via per-source queries and a broad+precise merge. On wearables in aging neuroscience, this combination removed retrieval noise, surfaced stronger evidence, and — through the merge — avoided losing a top marker to an over-strict query, while keeping every interpretive claim anchored to a field reference. The design is offered as a reproducible template for turning literature monitoring into a Level-3, decision-changing practice.
